# Caddy Web Server Support — Design

**Date:** 2026-08-14
**Status:** Approved (brainstorming complete)
**Approach:** Option A — Caddy as a third parallel web server, mirroring the existing nginx/Apache pattern.

## Goal

Add Caddy as a peer web server alongside nginx and Apache. Caddy is installable from the app catalog, runs as a managed service, generates per-site vhost configs in parallel with nginx/Apache, and integrates with the existing SSL/LAN-access/phpMyAdmin flows.

## Key decisions (from brainstorming)

1. **Role:** Caddy is a peer alongside nginx/Apache — sites generate nginx + apache + caddy vhost configs in parallel; the user chooses which server(s) to install/run.
2. **SSL:** Caddy uses the **same self-signed local certs** generated by `sslServiceProvider` (offline-friendly, identical to nginx/Apache). Caddy's automatic Let's Encrypt HTTPS is **disabled** (the generated Caddyfile points `tls` at the local cert).
3. **Vhost wiring:** An **import glob**, mirroring nginx. A main Caddyfile at the Caddy install root contains a `localhost` default block + `import "vhosts/caddy/*.conf"`. Per-site vhosts are individual files in `vhosts/caddy/<domain>.conf`.
4. **Approach:** Additive parallel branches across ~13 files, no `WebServerType` enum refactor (Option B deferred).

## Architecture

There is no `WebServerType` enum or web-server strategy interface. nginx and Apache are plain catalog entries (`appId` string-matched with `.contains('nginx')` / `.contains('apache')`) whose web-server-specific behavior lives in `if/else if` branches scattered across ~6 files. The catalog (`assets/data/apps.json`) is data-driven and is the registration mechanism. Caddy slots in by adding string-matched branches alongside the existing nginx/apache ones.

### 1. Catalog & install

**Catalog** — add a `caddy` entry to `assets/data/apps.json` (the source of truth; `new-apps.json` is unused staging):

```json
{
  "id": "caddy",
  "name": "Caddy",
  "description": "Fast, multi-platform web server with automatic HTTPS",
  "category": "webserver",
  "group_name": "webserver",
  "exec_file": "caddy.exe",
  "cli_file": "caddy.exe",
  "repo": "caddyserver/caddy",
  "versions": { "2.10.0": "<github release zip>", ... }
}
```

`category: "webserver"` makes `AppModel.isService` true automatically — no model change needed.

**Installer** (`lib/features/apps/data/app_installer_service.dart`):
- `_configureWebserver()` already triggers for `group_name == 'webserver'`. Add a Caddy branch alongside nginx/apache that:
  - Creates `vhosts/caddy/`.
  - Writes a main **Caddyfile** at the install root with a `localhost` default block + `import "vhosts/caddy/*.conf"` + `import "vhosts/caddy/integrations/*"`.
  - Reuses the existing localhost SSL-cert generation, `webserverRoot`, and `index.html` creation.
- The Caddy zip ships `caddy.exe` at the root (no `conf/` dir), so the Caddyfile is generated fresh — same as nginx's wholesale `nginx.conf` write, not Apache's patch approach.
- Extend `reconfigureWebservers()` and `syncInterAppConfigs()` filters to include `caddy`.

**Service manager** (`lib/features/apps/data/app_service_manager.dart`):
- Add `'caddy.exe'` to the `runsDetached` set (line ~358) — Caddy is a daemon like nginx.
- Add a `caddy.exe` args branch in `start()`: `['run', '--config', '<caddyfile>', '--adapter', 'caddyfile']`.
- In that branch, populate `requiredSockets` with 80/443 (Caddy binds both) for the pre-flight port-conflict check — an improvement nginx/apache currently lack.

**UI registration**:
- `compact_apps_table.dart` + `app_version_modal.dart`: add `caddy` cases to `_getIconFileName` / `_getAppIcon` / `_getIconColor` (Caddy brand green `#1F8C5B`), and add `assets/images/caddy.png`.
- `app_version_modal.dart` `conflictPairs`: Caddy binds 80/443 so it must conflict with both nginx and apache → `'caddy': 'nginx'`, `'caddy': 'apache'`, and reverse pairs. Mirrors the existing nginx↔apache mutual exclusion.

**Implementation verification detail:** exact Caddy release asset filenames and zip layout must be validated against the real GitHub releases when implementing. The version-link URLs are the one place real URLs must be confirmed.

### 2. Per-site vhost generation

All in `lib/features/sites/data/sites_provider.dart::_generateVhostFiles()`, mirroring nginx/apache.

**Directory & files** — create `vhosts/caddy/` alongside `nginx/` and `apache/`. Write per-site files to `vhosts/caddy/<domain>.conf` (the `.conf` suffix is kept for consistency with nginx/apache and so the existing `validateDomain` filename guard works unchanged; Caddy's `import` accepts the glob either way).

**`buildCaddyServer()`** — a new builder alongside `buildNginxServer`/`buildApacheServer`, translating the same site fields into Caddyfile syntax:

```
<domain> {
    bind <bindAddress>            # from WebserverBindPolicy.address(allowLanAccess)

    log {
        output file <logsPathUnix>/caddy_access.log
        level ERROR
    }

    # non-proxy:
    root * "<rootDirUnix>"
    php_fastcgi 127.0.0.1:<phpPort>     # siteType == 'php' (Caddy's bundled php_fastcgi preset)
    file_server

    # proxy (siteType == 'proxy'):
    reverse_proxy <safeTarget>
}
```

For SSL sites (`site.useSsl`), add `tls "<certPath>" "<keyPath>"` and serve on `:443` — using the **same self-signed certs from `sslServiceProvider`** (Caddy's auto-HTTPS disabled via `tls` pointing at the local cert). Generate one site block per port (80, optional 443) the same way nginx does.

**Bind policy** — add `WebserverBindPolicy.caddyBind()` / `caddySiteAddress()` helpers in `lib/core/config/webserver_bind_policy.dart`, returning the bind host for Caddy's `bind` directive (reusing the existing `address(allowLanAccess)` core). Keeps the LAN-access toggle working identically across all three servers.

**Wiring into existing accessors** — extend each to include caddy:
- `_removeVhostFiles()` — also delete `vhosts/caddy/<domain>.conf`.
- `getConfigs(site)` — add `'caddy'` to the returned map.
- `saveConfig(site, 'caddy', content)` — write to the caddy dir, then `restartWebservers()`.
- `getLogs(site)` — add `caddy_access` / `caddy_error` log keys.
- `restartWebservers()` filter (line ~924) — add `a.appId.contains('caddy')`.

**Validation / injection guards** — Caddyfile syntax uses `{ }` braces, so review the existing validators:
- `validateProxyTarget` already rejects `;{}` and control chars — covers Caddy's `reverse_proxy <target>` since braces are blocked. No change needed.
- `validateRootDir` rejects quotes/control chars — safe inside `root * "<path>"`. No change needed.
- Add a focused test confirming a brace-injected domain/root/target can't break the generated Caddyfile.

**Regeneration** — `regenerateAllVhosts()` loops all sites through `_generateVhostFiles`, so Caddy vhosts regenerate automatically on LAN-access/SSL toggles with no extra change.

### 3. Config editing, phpMyAdmin, and testing

**Config file resolution** — three places resolve a web server's main config path; add a Caddy branch to each:
- `webserver_settings_provider.dart::_getConfigFile()` → return `<installPath>/Caddyfile` for `caddy`.
- `app_settings_modal.dart::_getConfigFilePath()` → same Caddyfile path.
- `app_settings_modal.dart::_configTabLabel` → return `'Caddyfile'` for caddy.

**Syntax highlighting** — `lib/shared/widgets/code_editor/language_for_config.dart`. `re_highlight` 0.0.3 has **no Caddy mode** (ships apache, nginx, ini, json, yaml, plaintext — no caddy). Add `if (name == 'caddyfile') return langPlaintext;` as the safe fallback. Editor renders without a crash; users still get editing + the find/replace panel. A Caddy-aware highlighter is a future task, out of scope.

**Per-site config/log UI** — `lib/features/sites/presentation/widgets/edit_site_modal.dart`:
- `_ConfigTab`: the nginx/apache toggle buttons (plain-`TextField` editor) get a third `'caddy'` button; `_selectedType` default stays `'nginx'`. Reads/writes through `sitesNotifier.getConfigs`/`saveConfig` which carry the new `caddy` key.
- `_LogTab`: add Caddy access/error chips alongside the nginx/apache ones.

**phpMyAdmin integration** — `app_installer_service.dart::syncInterAppConfigs()` dispatches to `_configurePhpMyAdminInNginx()` / `_configurePhpMyAdminInApache()`, writing an integration vhost into `vhosts/<server>/integrations/`. For Caddy, add `_configurePhpMyAdminInCaddy()` writing a Caddyfile snippet into `vhosts/caddy/integrations/` and extend the filter to include `caddy`. The main Caddyfile template includes `import "vhosts/caddy/integrations/*"` to pull these in. **Fallback:** if phpMyAdmin integration proves Caddy-incompatible mid-implementation, gracefully exclude Caddy from `syncInterAppConfigs` (skip, don't crash) and document as a follow-up — goal is full parity.

**Testing** — mirror existing test files (codebase runs 139+ passing tests; additions keep that green):
- `webserver_bind_policy_test.dart` — add cases for `caddyBind`/`caddySiteAddress` (LAN vs localhost, port 80/443).
- `language_for_config_test.dart` — assert `Caddyfile` → plaintext.
- `proxy_target_test.dart` (or a new `caddy_injection_test.dart`) — assert a brace-injected proxy target is rejected and a clean generated Caddyfile round-trips.
- A `caddy_vhost_test.dart` — assert `buildCaddyServer` output for static/php/proxy site types and SSL on/off.

## Out of scope (explicit)

- No `WebServerType` enum refactor (Option B, deferred until a 4th server is needed).
- No Caddy admin API / JSON config adapter — Caddyfile adapter only.
- No automatic Let's Encrypt (self-signed local certs, per decision 2).
- No Caddy-specific syntax highlighter (plaintext fallback).
